## Библиотека

**Поддерживаемые форматы.** mp3, flac, ogg, oga, opus, m4a, m4b, mp4, aac, wav,
aiff, aif, wma, ape, wv, mpc, dsf, dff, alac. Теги читаются из ID3, Vorbis Comments,
MP4-атомов и APE — то есть у FLAC, MP3, M4A и OGG метаданные подхватываются нативно,
без внешних утилит.

**Структура.** Три уровня: исполнитель → альбом → трек. Альбом группируется по
`album_artist`, если тег есть, иначе по `artist` — так сборники не распадаются на
альбомы по каждому исполнителю.

**Что индексируется:** название, исполнитель, альбом, номер трека, год, жанр,
длительность, размер и время изменения файла, наличие встроенной обложки, хеш
содержимого.

**Отсутствующие файлы.** Полный скан помечает треки, чьих файлов больше нет, а не
удаляет их сразу: история прослушиваний и плейлисты сохраняются. Удалить окончательно —
командой `purge-missing` или из интерфейса.

**Виды библиотеки.** Три вкладки: исполнители, альбомы, плейлисты. Плитки с обложками,
альбомы листаются порциями («Показать ещё»), а не тянутся все сразу.

**Избранное и история.** Отметка «сердце» на треке, отдельный раздел «Избранное»,
раздел «Недавно прослушанные». Счётчики прослушиваний и время последнего — из тегов
плеера и Subsonic-клиентов.

**Плитка альбома** показывает обложку, название, исполнителя и год. **Страница альбома** —
обложка, название, ссылка на исполнителя, год, число треков, общая длительность, кнопки
«Играть альбом» и «В очередь», список треков с обложками.

**Навигация.** Хлебные крошки на страницах альбома и исполнителя: Библиотека / Альбомы /
Название. Возврат на любой уровень одним кликом.

## Воспроизведение и транскодирование

**Веб-плеер** с очередью, перемешиванием, повтором (выкл / всё / один), перемоткой по
клику на прогресс-баре, регулировкой громкости. Очередь можно заменить или дополнить.

**Форматы отдачи** (`format` в запросе стрима):

| Формат | Что делает |
|---|---|
| `raw` | Отдаёт файл как есть, без перекодирования |
| `mp3_128` | MP3 128 кбит/с |
| `mp3_256` | MP3 256 кбит/с |
| `mp3_320` | MP3 320 кбит/с |
| `mp3_v0` | MP3 VBR, качество 0 (≈245 кбит/с в среднем, до 320 на пиках) |
| `flac` | FLAC, сжатие уровня 5 |
| `alac` | ALAC в контейнере MP4 |

**Умная отдача.** Если исходник уже в нужном формате и с не большим битрейтом,
перекодирования не будет — отдаётся оригинал. Это экономит и процессор, и трафик.

**Ограничение параллельных транскодеров.** Не больше N одновременных ffmpeg-процессов
(по умолчанию 4). Если слоты заняты, сервер отвечает `503` с `Retry-After`, а не держит
клиент без ответа: иначе плеер решил бы, что сервер упал.

**Перемотка при транскодировании.** Поддерживается через смещение по времени. Для
форматов, которые нельзя скопировать потоком при смещении, используется запасной профиль
(`mp3_320`) — об этом пишется в журнал.

**HTTP Range.** Отдача файлов поддерживает частичные запросы, поэтому работает перемотка
в браузере и в клиентах.

**Формат по умолчанию** настраивается: если клиент не указал свой, применяется он.

## Обложки

**Три источника, по порядку:**

1. **Встроенная в файл** — ID3 (MP3), блок PICTURE (FLAC), атом `covr` (M4A/MP4),
   `METADATA_BLOCK_PICTURE` (OGG). Предпочитается «front cover», иначе первая найденная.
2. **Файл в каталоге альбома** — `cover.jpg`, `cover.jpeg`, `cover.png`, `cover.webp`,
   `folder.*`, `front.*` и похожие имена.
3. **Заглушка**, если картинки нет нигде.

**Уменьшение до 600 px.** Обложки режутся при первом извлечении и кешируются на диске:
полноразмерная картинка на слабом сервере — это десятки килобайт лишнего трафика и
заметная нагрузка. Поддерживается WebP, если декодер собран в Pillow.

**Кеш.** Записи в базе (`cover_cache`) плюс файлы в `/data/covers`. Отдельный
отрицательный кеш: «картинки нет» тоже запоминается, иначе сервер перебирал бы тысячи
альбомов без обложек при каждом запуске. Маркеры снимаются полным сканом.

**Фоновая фаза обложек.** Отдельный проход по альбомам без картинок, чтобы первое
открытие списка не ждало извлечения из тегов.

**Фаза уступает пользователю.** Пока вы листаете интерфейс, фоновая фаза ждёт: окно
активности (по умолчанию 3 с) и предельное ожидание одного альбома (по умолчанию 30 с).
Второе нужно, чтобы фон не встал совсем. Оба значения настраиваются без перезапуска.

**Обложки в списках грузятся пакетно.** Карточки ждут, пока сервер сообщит, что обложка
уже в кеше, — запросов «на всякий случай» нет. Это заметно на слабом сервере, где каждый
промах означает чтение файла и разбор тегов.

**Сборные обложки.** У плейлистов и «Избранного» — коллаж из четырёх обложек входящих
альбомов.

## Плейлисты

**Обычные плейлисты.** Создание, переименование, удаление, добавление и удаление
треков, изменение порядка.

**Умные плейлисты.** Правила вместо списка треков: состав считается при открытии,
поэтому плейлист не устаревает.

- **Сортировка:** название, исполнитель, альбом, число прослушиваний, дата добавления,
  длительность, дата последнего прослушивания, случайно.
- **Фильтры:** число прослушиваний, дата добавления, дата последнего прослушивания,
  длительность, год, жанр, исполнитель, альбом. Операторы: `=`, `≠`, `>`, `≥`, `<`, `≤`,
  а для дат — «за последние N дней» и «раньше N дней назад».
- **Безопасность.** Поля, операторы и сортировка берутся только из белых списков,
  значения идут параметрами. Правила приходят от пользователя и попадают в SQL,
  поэтому подстановка имени поля исключена по построению.

**Доступ.** Плейлист приватный или публичный. Редактировать может владелец или
администратор; смотреть публичный — любой пользователь.

**Экспорт.** В `.m3u8` — из интерфейса и через Subsonic `exportPlaylist`.

**Плейлист из папки.** Собирается из всех аудиофайлов указанной папки, порядок —
по имени файла. Файлы, которых нет в медиатеке, не добавляются, а перечисляются
отдельно: обычно это значит, что папку ещё не просканировали.

**Ресинк с папкой.** Проверка «что изменилось в папке с момента сборки»: превью
показывает, что добавится и что удалится, и только после подтверждения плейлист
обновляется. Удаление никогда не происходит на этапе превью.

## Импорт плейлистов

**Из `.m3u` и `.m3u8`.** Обход папки рекурсивно, со всеми подпапками. Пустой путь —
поиск по всей библиотеке.

**Сопоставление с медиатекой — три стратегии, от точной к мягкой:**

1. **По полному пути** — основной способ; путь нормализуется (обратные слэши, лишние
   сегменты).
2. **По префиксу** — если плейлист создан на другой машине (`M:\Music\...` или
   `/home/user/Music/...`). Задаётся пара «было → стало».
3. **По имени файла и исполнителю/названию** — запасной вариант. Возвращается
   несколько кандидатов, выбор делает человек: угадывать автоматически опаснее,
   чем показать варианты.

**Прогресс.** Разбор идёт фоновой задачей: сверху общий прогресс-бар и «Разбор
плейлистов N из M», ниже — карточка на каждый плейлист с его состоянием. Плейлисты
обрабатываются строго последовательно.

**Перед записью** видно, сколько треков сопоставлено из скольких, что не нашлось и
почему. Применение не разбирает папку заново — берёт уже готовый результат.

**Дубли имён.** `Rock/mix.m3u` и `Pop/mix.m3u` дают два плейлиста «mix». Оставляется
первый, остальные перечисляются в предупреждении — молча терять файлы нельзя.

**Форматы-пустышки.** HLS-плейлисты, пустые файлы и битые кодировки не создают
пустых «фантомных» плейлистов: ошибка показывается в карточке.

## Поиск

**Один запрос — три результата:** треки, альбомы, исполнители. Интерфейс показывает
все три группы, а не только треки.

**Где ищет:** название трека, исполнитель, альбом, имя исполнителя альбома.

**Безопасность шаблона.** Запрос экранируется: `%`, `_` и `\` не ломают шаблон `LIKE`
и не превращаются в подстановочные символы.

**Скорость.** Агрегаты по трекам считаются один раз (`GROUP BY`), а не подзапросом на
каждую строку. На 8 000 альбомов и 120 000 треков поиск альбомов — около 50 мс вместо
3,2 секунды.

**Отмена запросов.** Каждый новый ввод отменяет предыдущий запрос, устаревший ответ
отбрасывается. Без этого быстрый набор создавал очередь запросов, и сервер выглядел
зависшим.

## Пользователи и доступ

**Роли.** `admin` и `user`. Администратор видит разделы «Сканирование», «Импорт»,
«Пользователи», «Сервер» и может менять настройки.

**Первый запуск.** Пока в базе нет ни одной учётной записи, вход открывает страница
создания администратора. Пароль нигде в файлах не хранится — только хеш в базе.

**Пароли.** Хеширование с солью, без обратимого шифрования. Смена пароля завершает
все сессии пользователя, включая текущую на других устройствах.

**Сессии.** Список активных сессий с устройством, IP и временем последней активности;
любую можно завершить вручную.

**Защита от подбора.** Ограничение частоты попыток входа.

**Веб-безопасность.** Защита от CSRF для изменяющих запросов, строгий CSP без `unsafe-inline`,
`X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`.
Cookie сессии — `HttpOnly` и `SameSite`; флаг «только HTTPS» включается в настройках.

**HSTS сервер не выставляет.** Если нужен, включайте на уровне обратного прокси —
иначе при отладке по HTTP браузер надолго запомнит требование HTTPS.

**Секреты в журналах.** Пароли и токены вырезаются из логов, включая строки запросов
uvicorn.

## Subsonic API

Версия протокола — 1.16.1 (настраивается), плюс расширения OpenSubsonic.
Каждый метод доступен и как `/rest/<method>.view`, и как `/rest/<method>`.

**Система:** `ping`, `getLicense`, `getMusicFolders`, `getScanStatus`, `startScan`.

**Пользователи:** `getUser`, `getUsers`.

**Каталог:** `getArtists`, `getIndexes`, `getArtist`, `getAlbum`, `getAlbumList`,
`getAlbumList2`, `getSong`, `getGenres`.

**Поиск:** `search`, `search2`, `search3`.

**Потоки:** `stream`, `download`.

**Плейлисты:** `getPlaylists`, `getPlaylist`, `createPlaylist`, `updatePlaylist`,
`deletePlaylist`, `exportPlaylist`.

**Избранное и статистика:** `star`, `unstar`, `getStarred`, `getStarred2`,
`setRating`, `scrobble`.

**Обложки:** `getCoverArt` для ключей `al-<id>` (альбом) и `tr-<id>` (трек).

**Проверено с клиентами:** Symfonium, DSub, Ultrasonic. Другие клиенты, реализующие
Subsonic 1.16.1, обычно работают без настройки.

## Сканирование

**Два режима.** Инкрементальный читает только новые и изменённые файлы (сравнение
размера и времени изменения). Полный заново разбирает теги у всех файлов и помечает
отсутствующие.

**Наблюдение за папкой.** Автоматический скан при изменениях. По умолчанию выключено.
Поддерживается режим опроса (`polling`) — нужен на сетевых томах и Windows-монтированиях,
где inotify не работает.

**Интервальный скан.** Страховочный инкрементальный проход раз в N секунд. По умолчанию
выключен.

**Заходы по N треков.** Настройка «разбивать скан по треков» (0 — все сразу). Заходы
идут строго последовательно: следующий начинается после записи предыдущего. Маленькие
заходы дают ровный прогресс и короткие блокировки базы.

**Пачки записи.** Файлы разбираются параллельно, пишутся пачками по 100 в одной
транзакции. Ошибка одного файла откатывает только его (`SAVEPOINT`), остальные
сохраняются.

**Прогресс и история.** Процент, текущий этап, счётчики добавленных, обновлённых и
удалённых, таблица ошибок по файлам, история проходов.

**Отмена.** Скан можно прервать; уже записанное остаётся.

**Точечный скан.** Можно просканировать только указанную папку или файл, не обходя
всю библиотеку.

**Чтение не блокируется записью.** База работает в режиме WAL, веб-запросы идут через
отдельное соединение только для чтения и видят последний зафиксированный снимок.

## Архитектура

**Два процесса в одном контейнере:**

- **веб-сервер** — интерфейс, API, стриминг;
- **worker** — скан, наблюдение за папкой, фоновая фаза обложек.

Они не делят ни соединение с базой, ни event loop: пока идёт скан, интерфейс отвечает
нормально. Связь — через таблицу команд в базе и файл статуса, поэтому она переживает
перезапуск. Если worker падает, веб-сервер поднимает его сам и не оставляет сирот
после своей остановки.

**Две изолированные базы.** `mtr_users.db` — пользователи, сессии, настройки.
`mtr_music.db` — библиотека, плейлисты, обложки, история. Общих SQL-запросов между
ними нет.

**Миграции.** Версионируются через `PRAGMA user_version`, применяются при старте,
идемпотентны.

**Ключ шифрования** создаётся автоматически в `/data/secret.key` при первом запуске.

## Настройки

Меняются в интерфейсе, хранятся в базе, переживают пересоздание контейнера.
Часть применяется сразу, часть — после перезапуска (помечены в интерфейсе).

| Параметр | Смысл |
|---|---|
| Интервал скана | Страховочный инкрементальный скан, секунды. 0 — выключен |
| Заход скана | Сколько треков за один проход. 0 — все сразу |
| Лимит транскодов | Сколько ffmpeg-процессов одновременно |
| Параллельный разбор тегов | Сколько файлов читать одновременно при скане |
| Формат по умолчанию | Формат отдачи, если клиент не указал свой |
| Вид библиотеки по умолчанию | Исполнители / альбомы / плейлисты |
| Пауза обложек: окно | Сколько секунд после действия пользователя фаза ждёт |
| Пауза обложек: ожидание | Предельное ожидание одного альбома |
| Наблюдение за библиотекой | Автоматический скан при изменениях |
| Опрос вместо inotify | Режим для сетевых томов |
| Период опроса | Миллисекунды, только при включённом опросе |
| Уровень логов | DEBUG / INFO / WARNING / ERROR |
| Cookie только по HTTPS | Для работы через обратный прокси с TLS |
| Версия Subsonic API | Какую версию объявлять клиентам |
| Папка с плейлистами | Где искать `.m3u`/`.m3u8` |
| Заменять префикс путей | Пара «было → стало» для импорта |

Читаются из базы, а не из `.env` — файла `.env` в проекте нет.

## CLI

```bash
docker exec -it mtr-app python -m app.cli <команда>
```

| Команда | Что делает |
|---|---|
| `initdb` | Создать или миграционно обновить обе базы |
| `createuser` | Создать пользователя |
| `setpassword` | Задать пароль заново, без знания текущего (сброс) |
| `doctor` | Проверить конфигурацию и ключ шифрования |
| `scan` | Проиндексировать библиотеку (`--mode full` или `incremental`) |
| `stats` | Сводка по библиотеке |
| `purge-missing` | Удалить треки, чьи файлы исчезли |
| `covers` | Сбросить кеш обложек |
| `bench-covers` | Замерить стоимость извлечения обложек и выигрыш от кеша |

## Диагностика

**Раздел «Сканирование»** — прогресс, история проходов, ошибки по файлам, кнопки
«Пересканировать обложки» и «Очистить кэш обложек».

**Раздел «Сервер»** — версия, пути, версии схемы обеих баз, количество пользователей,
треков, отсутствующих файлов, обложек в кеше и их объём, состояние наблюдения.

**Самопроверка образа:**

```bash
docker exec mtr-app sh /app/scripts/selfcheck.sh
```

Проверяет Pillow и реальное уменьшение обложки, декодер WebP, ffmpeg, команды CLI,
наличие монтирований.

**Журнал:** `docker logs -f mtr-app` — оба процесса в одном потоке.

## Ограничения

Честно о том, чего нет или что стоит знать заранее.

- **Нет HTTPS из коробки.** Сервер отдаёт HTTP. Для HTTPS нужен обратный прокси
  (Caddy, nginx, встроенный прокси QTS) или туннель. Флаг «cookie только по HTTPS»
  в настройках уже есть.
- **Нет встроенного каталога IP-адресов.** Публичный сертификат на голый IP получить
  нельзя, нужен домен или внутренний CA.
- **Нет транскодирования в AAC и Opus.** Доступные профили перечислены выше.
- **Нет офлайн-кеша на клиенте.** Это задача клиентского приложения, а не сервера.
- **Умные плейлисты не хранят состав.** Он пересчитывается при каждом открытии — это
  осознанный выбор, но на очень больших правилах открытие будет заметно медленнее.
- **Один экземпляр.** Горизонтального масштабирования нет: worker один, база одна.
- **Проверка на реальных объёмах ограничена.** Замеры делались на синтетических
  библиотеках; поведение на конкретном NAS может отличаться.
