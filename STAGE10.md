# Этап 10 — Чистая пересборка и самопроверка образа

Версия 0.17.0. Тема этапа: прекратить ловить «образ собран из смеси файлов»
и получить способ убедиться в этом одной командой.

## Что произошло

`docker exec mtr-app python -c "import app; print(app.__version__)"` отвечал
`0.16.0`, а `python -m app.cli --help` показывал набор команд от 0.14.0, и
`import PIL` падал с `ModuleNotFoundError`. Три факта, несовместимых друг с
другом: в одном образе лежали `__init__.py` от новой версии и `cli.py` с
`requirements.txt` от старой.

Причина — порядок слоёв в Dockerfile. `COPY app ./app` идёт после
`RUN pip install -r requirements.txt`. Слой `pip install` кешируется по
контрольной сумме `requirements.txt`. Если файл на диске не заменился (архив
распаковался не полностью или не туда), Docker видит тот же самый
`requirements.txt`, переиспользует старый слой — и Pillow в образ не попадает.
При этом `COPY app` забирает то, что реально лежит в каталоге. Отсюда смесь.

Вывод: `docker compose up -d --build` без `--no-cache` не гарантирует, что
новые зависимости установятся.

## Что добавлено

### 1. Скрипт полной чистки и пересборки — `scripts/clean-rebuild.sh`

Делает по шагам:

1. проверяет каталог данных и наличие `secret.key` — **данные не трогает**;
2. удаляет контейнер `mtr-app`;
3. удаляет все образы `mtr-app:*`, а не только текущий тег;
4. чистит кеш сборки (`docker builder prune -af`);
5. собирает `docker compose build --no-cache`;
6. поднимает и ждёт `/healthz`;
7. запускает самопроверку и завершается с кодом 1, если что-то не на месте.

Данные лежат на хосте в `/share/CACHEDEV1_DATA/Container/mtr-data` и
монтируются в `/data`. Скрипт удаляет только контейнер и образы.

### 2. Самопроверка — `scripts/selfcheck.sh`

Семь проверок, каждая отвечает на конкретный прошлый сбой:

| Проверка | Что ловит |
|---|---|
| `covers` в CLI | старый `cli.py` |
| `bench-covers` в CLI | старый `cli.py` |
| `import PIL` | не установился Pillow |
| ресайз 1200×1200 → 600×600 | Pillow есть, но `make_thumbnail` не работает |
| `ffmpeg` доступен | сломан стриминг |
| `/music` смонтирован | пустой том вместо папки |
| `/data` смонтирован | база уйдёт внутрь контейнера |

Проверка ресайза — не `import`, а реальный вызов: создаётся картинка
1200×1200 в памяти, прогоняется через `make_thumbnail`, проверяется, что
результат ровно 600×600. Импорт может пройти, а функция — падать.

Добавлена в образ (`COPY scripts ./scripts` в Dockerfile), поэтому работает
внутри контейнера:

```bash
docker exec mtr-app sh /app/scripts/selfcheck.sh
```

### 3. Версия 0.17.0 и тег образа `mtr-app:0.17.0`

Версия поднята намеренно. Прежний смешанный образ тоже отвечал `0.16.0`,
поэтому по номеру версии его нельзя было отличить от правильного. Теперь
`0.17.0` означает: собран из этого архива, Pillow на месте.

## Замер на реальном NAS (TS-431, armv7)

Присланный вывод:

```
обработано 60: готово 59, без картинки 1, ошибок 0
прошло 9 с
```

Это **150 мс на альбом** — в 3,5 раза медленнее песочницы (43 мс), что для
armv7 с чтением по сети ожидаемо. Отсюда:

* прогрев всех 9289 альбомов ≈ **23 минуты** (9289 × 0,15 с);
* открытие сетки из 60 карточек холодным ≈ 9 с, из кеша ≈ 0,02 с.

Одна обложка без картинки из 59 — нормальный результат: примерно у 2%
альбомов картинки в тегах действительно нет.

### Таймер встроен в команду `covers`

Раньше замер требовал однострочника в шелле. Теперь `covers` печатает всё
сама:

```
обработано 10: готово 10, без картинки 0, ошибок 0
прошло 0.2 с (25 мс на альбом)
осталось 15 альбомов — при той же скорости это меньше секунды
доготовить всё: python -m app.cli covers
в кеше 10 обложек, 101 КБ на диске
```

Что даёт: видно скорость на альбом, остаток и оценку времени, а также
занятое место. Для 9289 альбомов последняя строка покажет реальный объём
кэша в мегабайтах.

### Найден и исправлен баг форматирования

Порог «до 90 минут» в `_human_duration` не давал перейти в часы: 3600 с
показывались как «60 мин». Второй: 90 КБ превращались в «0 МБ», потому что
размер считался только в мегабайтах.

Оба видны глазом, но оба — признак ошибки в расчёте, поэтому на них
написаны тесты (`tests/test_cli_covers_output.py`, 4 теста).
