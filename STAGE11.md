# Этап 11 — Плейлист из папки и ресинк с папкой

Версия 0.18.0. Схема `mtr_music` — v4.

## Что сделано

1. **Сборка плейлиста из папки.** `app/playlists/folder_sync.py: scan_folder_to_playlist`.
   Рекурсивный обход, батч-поиск треков по пути (`IN`, пачками по 300), сортировка
   подпапка → диск → трек. Имя по умолчанию — имя корневой папки.
2. **Ресинк.** `build_resync_plan` (превью, ничего не пишет) и `apply_resync_plan`
   (применение). Проверка свежести медиатеки по `MAX(finished_at)` из `scan_runs` с допуском
   1 с. Поиск перемещённых треков — два батча: по `content_hash` и по `(artist, album, title)`.
   Удаление только для подтверждённых `link_id`.
3. **HTTP.** `app/web/folder_api.py`: сборка и превью — фоновые задачи с опросом прогресса,
   подтверждение — одноразовый токен. Ошибки — с кодом (`library_stale` → 409).
4. **Интерфейс.** `app/web/static/folder_sync.js`: блок сборки (путь редактируется в input),
   блок ресинка (выбор плейлиста, список изменений, чекбоксы для удаления, диалог
   подтверждения), полосы прогресса на обоих блоках.
5. **Миграция v4.** Индексы `tracks(content_hash)`, `tracks(artist, album, title)`,
   `playlist_tracks(playlist_id, position)`, колонки `playlists.origin_folder_path`
   и `playlists.synced_at`.
6. **selfcheck.** Проверка ffmpeg теперь реальная. Проверки монтирований `/music` и `/data`
   выполняются только внутри контейнера (наличие `/.dockerenv`). Вне контейнера они помечаются
   как ПРОПУЩЕНО и не считаются ошибкой.

## Проверки

- `pytest`: все тесты, включая новые `tests/test_folder_sync.py` и `tests/test_folder_api.py`
  (сценарии: сортировка, пустой unmatched, устаревшая медиатека, перемещение с сохранением
  позиции, удаление только после подтверждения, добавление новых файлов, миграция v3→v4,
  одноразовость превью, права).
- `node tests/js/headless.js`: проверки интерфейса импорта.
- `sh scripts/selfcheck.sh`: ffmpeg OK, монтирования пропущены вне контейнера.

## Известные ограничения

- Хэш ленивый, поэтому для треков без `content_hash` работает только поиск по тегам.
- Треки без исполнителя или альбома по тегам не сопоставляются.
- Прогресс и превью живут в памяти процесса.
- Сборка работает по одной папке за запуск (например, `/music/Дискографии/Artist1`).
  Пакетная сборка по всем артистам в одном запуске не реализована.
