# Этап 13 — Прогресс обложек после скана, WebP, статус скана

Версия 0.20.0.

## Что исправлено

1. **Статус скана не обновлялся без перезагрузки.** После нажатия «Сканировать»
   страница перерисовывалась до того, как скан начинал работать. Опрос стартовал
   только при уже идущем скане при открытии раздела, поэтому данные появлялись
   только после обновления. Теперь опрос запускается сразу после запуска скана.
2. **Тесты обложек падали.** Ожидания тестов не совпадали с поведением:
   - второй запрос к кэшу действительно шёл из кэша, тест считал вызовы первого запроса;
   - маркер «обложки нет» живёт в БД и переживает сброс памяти (это задумано),
     тест ожидал обратное. Тесты приведены в соответствие с документацией.

## Что добавлено

3. **Прогресс обложек после скана.** Фаза `CoverPass` стартует по завершении скана.
   В статусе и в строке UI видны: состояние, `done из total`, сделано, без картинки,
   ошибки, текущий альбом и время на него (если больше 5 с). Строка выводится
   и в разделе «Сканирование», и на главной библиотеки.
4. **Доступность сразу.** Альбомы попадают в БД и в сетку при скане, не дожидаясь
   фазы обложек. Обложки подгружаются лениво через `getCoverArt`.
5. **WebP.** Проверка декодера — реальным декодированием тестового файла, а не флагом
   `features.check`. Если декодера нет, обложка WebP отдаётся как есть. Ошибок не
   возникает, варнинг Pillow не выводится. `selfcheck` показывает статус.

## Ограничения

- Проверка на **arm/v7 не выполнена**: в песочнице нет эмуляции (нет qemu, docker,
  binfmt), а колесо Pillow 12.1.0 для armv7 доступно только с piwheels. Поведение
  без libwebp проверено симуляцией, не на устройстве. Проверить на NAS:
  `docker exec mtr-app python -c "from app.covers.service import webp_support; print(webp_support())"`
- Точное время на альбом на NAS не замерено. Текущий альбом и время на него теперь
  видны в UI: если альбом висит, будет видно, на каком он.
