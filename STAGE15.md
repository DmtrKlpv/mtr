# Этап 15 — Списки без ожидания обложек

Версия 0.20.2.

## Проблема

Открытие альбомов, исполнителей и плейлистов ставило в очередь запрос `getCoverArt`
на каждую карточку. Промах кеша означает извлечение обложки из тегов на сервере:
чтение файла и разбор тегов на NAS. Во время скана это шло параллельно индексации,
отсюда подвисания и замедление.

## Что сделано

1. **Списки рисуются сразу.** Карточка создаётся с заглушкой и не запрашивает обложку сама.
2. **Пакетная проверка готовности.** `GET /api/web/covers/ready?keys=al-1,tr-2,…` отвечает
   по таблице `cover_cache`: `ready` или `absent`. Файлы не читаются, обложки не извлекаются.
   Ключи валидируются: принимаются только `al-<число>` и `tr-<число>`, не более 500 за запрос.
3. **Клиентская очередь.** Карточки собираются, раз в 1,5 с уходят пачкой по 60 ключей.
   `ready` — подставляется `src` на `getCoverArt` (уже из кеша). `absent` — заглушка, без
   повторных запросов. Ключа нет в ответе — проверим на следующем тике.
4. **Пауза во время скана.** Пока статус скана или фазы обложек `running`, очередь не
   опрашивает сервер. После завершения возобновляется.
5. **Фаза обложек не меняется.** Она по-прежнему идёт после скана и заполняет `cover_cache`.
   По мере заполнения карточки получают обложки.

## Что проверено

- `tests/test_covers_ready.py`: эндпоинт не извлекает обложки (счётчик вызовов извлечения = 0);
  возвращает `ready`/`absent` только для ключей с записью; фильтрует мусорные ключи; требует сессию.
- Полный `pytest`, `headless.js`, `selfcheck`.

## Не проверено

- Поведение в браузере на NAS: скорость прокрутки, появление обложек по мере фазы.
- Подвисания на реальной библиотеке: нужен замер на устройстве.

## Открытые вопросы

- Пауза фазы обложек при активности пользователя (не только при скане) не сделана.
  Сейчас фаза работает параллельно просмотру; при желании её можно притормаживать,
  пока открыт список.
