# Этап 20 — Крошки, баннер установщика, прогресс импорта m3u

Версия 0.23.2.

## 1. Крошка «Альбомы» вела на главную

**Причина.** `switchLibraryTab('albums')` вызывал `setView('library')`, а `renderLibrary`
рисует главную целиком: приветствие, поиск, «Недавно добавленное», секции, и только потом
список. Прокрутка в прошлой версии проблему не решала: список всё равно был частью главной.

**Что сделано.** Появился отдельный вид `albums` (`renderAlbumsView`): крошки, заголовок,
переключатель вкладок и сетка альбомов — больше ничего. Крошка и вкладка «Альбомы» ведут на него.
Переключатель вынесен в `librarySwitcher()` и используется и на главной, и в новом виде.

## 2. Баннер в `install-in-docker.sh`

**Причина смещения.** У буквы `R` верхние две строки в арте были на 2 символа короче
остальных (32 против 34), поэтому каждая строка «уезжала» на символ.

**Что сделано.** Арт пересобран из трёх блоков по 10 символов с двумя пробелами между ними:
ширина всех строк ровно 34. Версия печатается под артом и центрируется вычислением
(`(34 - длина) / 2`), а не подбором пробелов.

Версия берётся так: `python3 -c "import app; print(app.__version__)"` → `python` (на случай
другого имени) → `grep` из `app/__init__.py` → «нет». На хосте, где установлен только Docker,
Python может отсутствовать, и падать из-за этого нельзя. Цвет включается только при выводе
в терминал (`[ -t 1 ]` и `NO_COLOR`), чтобы в `docker logs` не было escape-последовательностей.

## 3. «Очистить кэш обложек» убрана из «Сервера»

Кнопка осталась только в разделе «Сканирование», рядом с «Пересканировать обложки».
В «Сервере» продублирована не была нужна.

## 4. Импорт m3u с прогрессом

**Причина зависания.** Разбор папки был одним синхронным запросом `GET /preview`,
пока он шёл — на экране висело «Разбираю папку…» без единой цифры. На большой библиотеке
это минуты. Хуже: `POST /apply` разбирал папку заново, то есть ожидание повторялось.

**Что сделано.**

- `app/playlists/import_jobs.py`: задача импорта с общим этапом и состоянием каждого плейлиста.
- `POST /api/web/playlists/import/start` — запускает разбор в фоне, отдаёт `id`.
- `GET /api/web/playlists/import/jobs/{id}` — прогресс: `stage` (walk → playlists → done),
  `done/total`, `percent`, `current` и список `items` — по элементу на плейлист
  (`pending | parsing | matching | done | error`).
- Плейлисты обрабатываются строго последовательно: следующий после предыдущего,
  поэтому прогресс не скачет назад.
- `POST /apply` принимает `job_id` и берёт готовые планы из задачи — повторного разбора нет.
- В интерфейсе: сверху общий прогресс-бар и «Разбор плейлистов N из M», ниже — карточки
  по каждому плейлисту с его собственным состоянием.

## 5. Компактный список импорта, жёлтый знак вопроса

- Высота карточек меньше: отступы 9/12 px вместо 14/16, метаданные в одну строку
  с названием, `select` компактнее.
- Вместо крутящегося спиннера — жёлтый знак вопроса (`icons/help.svg`, CSS `.import-status.pending`):
  «ещё не обработан». Во время работы он сменяется на состояние, в конце — галочка или крестик.
