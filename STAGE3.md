# Этап 3 — Subsonic API и авторизация

## Аутентификация
Три способа (по спецификации 1.16.1):
- `t` + `s` — `md5(password + salt)`, основной;
- `p=enc:<hex>` — устаревший, но поддерживается;
- `p=<plain>` — работает, в лог пишется предупреждение.

JWT — код 41 (честный отказ, а не «неверный пароль»).
Неизвестный пользователь и неверный пароль дают один и тот же ответ (код 40),
чтобы нельзя было перебирать логины.

Троттлинг: 10 неудач за 5 минут по ключу `username|ip` → временная блокировка.
IP берётся из `request.client`, а не из `X-Forwarded-For` (подделывается).
Проверка `last_login_at` пишется не чаще раза в 5 минут — иначе каждый
запрос плеера был бы записью в БД.

## Методы
`ping`, `getLicense`, `getMusicFolders`, `getScanStatus`, `startScan`(admin),
`getUser`, `getUsers`(admin), `getArtists`, `getIndexes`, `getArtist`,
`getAlbum`, `getAlbumList`, `getAlbumList2`, `getSong`, `getGenres`,
`search`, `search2`, `search3`, `stream`, `download`.

Каждый метод доступен как `/rest/<method>.view` и `/rest/<method>`.

## Коды ошибок
| ситуация | код | HTTP |
|---|---|---|
| нет параметра | 10 | 200 |
| неверные учётные данные | 40 | 200 |
| JWT вместо токена | 41 | 200 |
| нет прав (не admin) | 50 | 200 |
| не найдено | 70 | 200 |
| stream/download без авторизации | — | **401** |
| stream/download: не найдено | 70 | 200 |

Разница намеренная: JSON-методы следуют протоколу (HTTP 200 + код в теле),
бинарные — HTTP-семантике, иначе плеер не понимает, что нужен пароль.

## Закрытие дыры этапа 2
`/stream` больше не открыт: требует те же `u/t/s/p`, отдаёт 401 без них.

## maxBitRate
Потолок клиента учитывается при выборе профиля:
`maxBitRate=128` на FLAC → `mp3_128` (не FLAC, иначе мобильный клиент захлебнётся).

## Не реализовано (этапы 4-7)
Плейлисты, звёздочки, scrobble, обложки, бронирование, share, аннотации.
Флаги ролей в `getUser` выставлены честно: `uploadRole=false`,
`commentRole=false` и т.д., чтобы клиент не показывал нерабочие кнопки.

## Исправление: дисциплина транзакций (v0.3.1)

Найдено при импорте библиотеки: `cannot start a transaction within a transaction`
и, что опаснее, потеря данных при конкурентных записях.

Причины (все три подтверждены воспроизведением):
1. Неявный BEGIN модуля sqlite3 (`isolation_level=""`) — после любого INSERT
   соединение уже в транзакции, и последующий `BEGIN IMMEDIATE` падает.
   Исправлено: `isolation_level=None`, транзакции явные.
2. Счётчик вложенности `_tx_depth` общий на соединение, а не на задачу.
   Задача B, вошедшая в чужую транзакцию, не открывала своей, и при падении A
   откатывалась и её работа, хотя B получила «успех».
   Исправлено: транзакция принадлежит задаче (`_tx_owner`), чужие задачи ждут.
3. Вложенный блок откатывал всю транзакцию целиком. Исправлено: SAVEPOINT.
   Сбой COMMIT/ROLLBACK больше не проглатывается молча.

Регрессионные тесты: tests/test_transactions.py.

## Исправление v0.3.2: восстановление после смены MTR_SECRET_KEY

**Симптом:** `/rest/ping.view` с верным токеном и с верным паролем отдаёт код 40.
`docker logs` показывает `нет доступа к паролю пользователя 'admin'`.

**Причина:** проверка пароля шла через `get_plain_password()`, то есть требовала
расшифровки Fernet. При смене ключа расшифровка невозможна, и оба способа
аутентификации падали одинаково — хотя PBKDF2-хэш остался валидным.

**Исправлено:**
1. Ветка `p=` проверяется по PBKDF2-хэшу и **не зависит от ключа**.
2. После успешного входа паролем обратимая копия перешифровывается текущим
   ключом — token-авторизация восстанавливается автоматически.
3. `python -m app.cli doctor` — диагностика (код возврата 1 при проблемах).
4. `python -m app.cli setpassword --username <имя>` — принудительный сброс.
5. `bootstrap` предупреждает в логе, что MTR_ADMIN_PASSWORD проигнорирован,
   если пользователи уже есть.
6. Диагностика запускается при старте сервера и пишет проблемы в лог.

**Порядок восстановления на сломанной базе:**
1. `docker exec -it mtr-server python -m app.cli doctor` — увидеть причину.
2. Войти паролем: `/rest/ping.view?u=admin&p=<пароль>&v=1.16.1&c=x` — 
   токен починится сам.
3. Либо жёстко: `python -m app.cli setpassword --username admin`.
