# Этап 9 — Без `.env`: сборка и настройка только через Docker

Версия 0.16.0. Тема этапа: убрать скрытый файл `.env`, из-за которого пути
молча не применялись, и собрать всё в одну точку — `docker-compose.yml` плюс
интерфейс.

## Что было не так

`docker run` не читает `.env` — это формат compose. Если в команде стояло
`-v ${MUSIC_PATH}:/music`, а переменная не объявлена, оболочка подставляла
пустую строку, и Docker получал `-v ":/music"`. Это **валидная** запись:
«создай анонимный том». Ошибки нет, внутри пусто, а имя источника выглядит
как хеш:

```
.../volumes/8e9ef7ff8149.../_data -> /music
```

Именно так и получилось. Диагностировать это по логам было почти невозможно.

## Куда что переехало

| Что | Где теперь | Почему |
|---|---|---|
| Пути к музыке и данным | `docker-compose.yml`, буквально | Docker не знает путей хоста из образа |
| Порт | `docker-compose.yml` | проброс портов — дело Docker |
| Администратор | страница первого запуска | пароль не должен лежать в файлах |
| Ключ шифрования | создаётся сам в `/data/secret.key` | лежит рядом с данными, переживает пересоздание |
| Интервал скана, наблюдение, опрос, лимит транскодеров, логи, формат отдачи | Настройки → Сервер | читаются из базы при старте |

Пути к музыке физически не могут жить в образе: образ не знает, на каком
хосте его запустят. Это ограничение Docker, а не кода. Убрана не
необходимость их указывать, а необходимость держать их в отдельном скрытом
файле и риск молча получить пустой том.

## Страница первого запуска

Новый маршрут `/setup` и эндпоинт `POST /api/web/setup`.

- Открывается автоматически: `/login` редиректит на `/setup`, если в базе нет
  ни одной учётной записи. Иначе человек видел бы форму входа, за которой
  некому открыть дверь.
- Пока администратор не создан, страница доступна; после создания — 303 на
  `/login`. Это защита: иначе любой мог бы добавить себе админский аккаунт.
- Пароль проверяется теми же правилами (не короче 8 символов), попадает в
  базу хешем плюс обратимой копией для Subsonic-токенов.
- Сразу выдаются сессия и CSRF-cookie — отдельный вход после создания не нужен.

Переменные `MTR_ADMIN_USER` / `MTR_ADMIN_PASSWORD` удалены вместе с функцией
`_bootstrap_admin_if_requested`. Проверка правды: на пустой базе без единой
переменной окружения сервер поднимается, `/setup` отдаёт форму, создание
админа возвращает 200 и cookies `mtr_session` + `mtr_csrf`, `/app` — 200.

## Настройки из базы применяются до создания подсистем

Была скрытая проблема: `AppContext.create` создавал наблюдатель
(`LibraryWatcher`) с параметрами из конфига, а переопределения из базы
применялись **после**, в `lifespan`. Поэтому «период опроса» и «режим опроса»
из интерфейса до `watchfiles` не доезжали — он получал их в конструкторе.

Теперь `all_overrides()` читается в `create`, до создания сканера, наблюдателя
и ограничителя транскодеров:

```python
stored = await settings_repo.all_overrides()
if stored:
    settings = dataclasses.replace(settings, **applicable)
```

Приоритет стал честным: **база главнее переменных окружения и файлов**. Раньше
это было заявлено в комментариях, но не выполнялось для restart-ключей.

## Диагностика монтирования

В `run_doctor` добавлена проверка `_check_mounts`. Два признака:

1. **Каталог музыки пуст, а в базе есть треки** — почти наверняка смонтирован
   не тот том. Сообщение прямо называет причину и подсказывает, что смотреть:
   ```
   ПРОБЛЕМА: база знает 35879 треков, но каталог /music пуст — похоже,
   вместо папки с музыкой смонтирован пустой том. Проверьте docker inspect:
   источник у /music должен быть путём на хосте (/share/...), а не
   .../volumes/<хеш>/_data
   ```
2. **Записей в каталоге меньше 1% от числа треков в базе** (при 50+ треках) —
   возможно, смонтирована не та папка.

Проверка не срабатывает на пустой базе: там пустой каталог — это нормальный
первый запуск, а не ошибка. Отдельное поле `music_mount_suspicious` в отчёте
для программной проверки.

## Docker

`env_file`. Добавлен `build`, чтобы `docker compose up -d --build` собирал
образ из локального контекста, а не искал его в реестре.

`.env.example` удалён. `.gitignore` почищен.

## Известные ограничения

* Смена «режима опроса» и «периода опроса» требует перезапуска контейнера:
  `watchfiles` получает их в конструкторе. На странице настроек это указано.
* `MTR_SECRET_KEY` как переменная окружения всё ещё поддерживается и
  **перебивает файл**. Если задать её один раз и убрать, сервер вернётся к
  файлу — а это другой ключ. В README написано, что использовать её не нужно.
* E2E-тесты в браузере (`tests/e2e`) требуют поднятого сервера и не
  запускались.
